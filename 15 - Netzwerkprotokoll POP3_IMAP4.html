15 - Netzwerkprotokoll POP3 / IMAP4

1. Wie funktioniert der Mailtransfer im Internet generell?

Wenn man eine E-Mail verschickt, läuft der Prozess in mehreren klar getrennten Phasen ab. Wichtig ist:
Senden und Empfangen sind zwei verschiedene Dinge - technisch sogar komplett unterschiedliche Protokolle.

Der Ablauf sieht vereinfacht so aus:

  1. Du schreibst eine Mail in deinem Mailprogramm.
  2. Dein Mailclient sendet die Mail per SMTP an deinen Mailserver.
  3. Dieser Mailserver ermittelt über DNS (MX-Record) den zuständigen Mailserver der Empfänger-Domain.
  4. Die Mail wird per SMTP (Port 25) an den Zielserver der Empfänger-Domain.
  5. Der Zielserver speichert die Mail im Postfach des Empfängers.
  6. Der Empfänger ruft seine Mail mit POP3 oder IMAP ab.

SMTP ist also das Transportprotokoll.
POP3 und IMAP sind Abrufprotokolle.

Man kann sich das wie die Post vorstellen:

  • SMTP = Zustellung zum Briefkasten
  • POP3/IMAP = Brief aus dem Briefkasten holen

2. An welchen Stellen wird SMTP, POP3 oder IMAP verwendet?

SMTP wird ausschließlich zum Versenden und Weiterleiten von E-Mails verwendet. Es ist nie dafür gedacht gewesen, Mails beim Benutzer bereitzustellen.

POP3 und IMAP werden ausschließlich zum Abrufen von E-Mails aus einem Postfach verwendet.

Zusammengefasst:

  • Client ⟶ Server (Versand): SMTP
  • Server ⟶ Server (Weiterleitung): SMTP
  • Client ⟶ Server (Abruf): POP3 oder IMAP

Diese klare Trennung ist ein Grundprinzip der E-Mail-Architektur.

3. Bedeutung der Abkürzungen

SMTP steht für Simple Mail Transfer Protocol - einfaches Protokoll zum Übertragen von E-Mails.

POP3 steht für Post Office Protocol Version 3 - ein Protokoll zum Abholen von Post aus einem Postfach.

IMAP steht für Internet Message Access Protocol - ein Protokoll zum Zugriff auf Nachrichten auf einem Server.

Schon an den Namen erkennt man:
POP3 holt Post ab.
IMAP erlaubt Zugriff auf Nachrichten.

Das klingt ähnlich, ist technisch aber ein riesiger Unterschied.

4. TCP-/UDP-Ports der Protokolle

Alle drei Protokolle arbeiten über TCP, da eine zuverlässige Übertragung benötigt wird.

SMTP:

  • Port 25 ⟶ Server-zu-Server
  • Port 587 ⟶ Client Submission
  • Port 465 ⟶ SMTP über TLS (implicit TLS)

POP3:

  • Port 110 ⟶ unverschlüsselt
  • Port 995 ⟶ POP3 über TLS

IMAP:

  • Port 143 ⟶ unverschlüsselt
  • Port 993 ⟶ IMAP über TLS

Wichtig:
POP3 und IMAP verwenden kein UDP.

5. Unterschied zwischen POP3 und IMAP

Hier liegt der eigentliche Kern des Themas.

POP3 - "Download und fertig"

POP3 arbeitet nach einem einfachen Prinzip:

  • Verbindung zum Server
  • Authentifizierung
  • Abruf aller Mails
  • Mails werden meist lokal gespeichert
  • Optional: Löschen auf dem Server

Das bedeutet:
POP3 ist dafür gedacht, Mails lokal zu speichern und den Server eher als temporären Speicher zu nutzen:

Typische Eigenschaften:

  • Kein serverseitiger Ordnerabgleich
  • Kein Synchronisieren zwischen mehreren Geräten
  • Sehr einfaches Protokoll
  • Geringer Serverbedarf

POP3 passt gut in Szenarien mit nur einem Endgerät.

IMAP - "Server ist die Wahrheit"

IMAP funktioniert völlig anders.

Hier bleiben die Mails dauerhaft auf dem Server gespeichert.
Der Client synchronisiert nur:

  • Gelesen/Ungelesen Status
  • Ordnerstruktur
  • Verschieben von Mails
  • Löschen
  • Markierungen

Das bedeutet:

Wenn du auf deinem Handy eine Mail als gelesen markierst, ist sie auf deinem PC ebenfalls gelesen.

IMAP ist also ein Synchronisationsprotokoll, kein reines Abrufprotokoll.

Typische Eigenschaften:

  • Mehrere Geräte gleichzeitig
  • Serverseitige Ordner
  • Status-Synchronisation
  • Höherer Ressourcenbedarf auf dem Server

In modernen Umgebungen ist IMAP Standard.

-- PRAKTISCHER TEIL --

Vorbereitung: hMailServer installieren

hMailServer ist ein kostenloser Mailserver für Windows, mit dem man SMTP, POP3 und IMAP lokal betreiben kann.

Installation
  • Download von der offiziellen Website
  • Installation durchführen
  • Administrationskonsole starten
Domain einrichten

In hMailServer wird zunächst eine Domain angelegt, z. B.:

mail.local

Innerhalb dieser Domain wird ein Postfach erstellt, z. B.:

max@mail.local

Dieses Postfach erhält ein Passwort.

Damit existiert ein vollständiger lokaler Mailserver.

SSL-Zertifikat einbinden

Für verschlüsselte Verbindungen benötigt man ein Zertifikat.

Grundprinzip:

  1. Zertifikat im Server hinterlegen
  2. SMTP/POP3/IMAP auf TLS konfigurieren
  3. Ports 465, 995, 993 aktivieren

Technisch passiert Folgendes:

Beim Verbindungsaufbau wird ein TLS-Handshake durchgeführt:

  • Server sendet Zertifikat
  • Client prüft Vertrauenswürdigkeit
  • Sitzungsschlüssel wird ausgehandelt
  • Kommunikation wird verschlüsselt

Wichtig:
SSL ist veraltet. Verwendet wird TLS.

Praktischer Ablauf per Telnet

1. SMTP per Telnet

Verbindung herstellen:

telnet localhost 25

Typischer Ablauf:

HELO test
MAIL FROM: sender@mail.local
RCPT TO: max@mail.local
DATA
Testnachricht
.
QUIT

Wichtig:
Der Punkt allein in einer Zeile beendet DATA.

Damit wurde die Mail an hMailServer zugestellt.

POP3 per Telnet

Verbindung:

telnet localhost 110

Ablauf:

USER max@mail.local
PASS passwort
LIST
RETR 1
QUIT

POP3 lädt die Nachricht vollständig herunter.

IMAP per Telnet

Verbindung:

telnet localhost 143

IMAP arbeitet mit nummerierten Befehlen:

a1 LOGIN max@mail.local passwort
a2 SELECT INBOX
a3 FETCH 1 BODY[]
a4 LOGOUT

IMAP zeigt die Nachricht an, ohne sie zwingend zu löschen.

Hier sieht man sehr gut:
POP3 ist simpel.
IMAP ist deutlich komplexer.

Funktionsweise der SSL/TLS-Verschlüsselung (kurz erklärt)

TLS arbeitet nach folgendem Prinzip:

  1. Client verbindet sich mit Server
  2. Server sendet Zertifikat
  3. Client prüft Zertifikat
  4. Beide handeln einen Sitzungsschlüssel aus
  5. Ab jetzt ist die Verbindung symmetrisch verschlüsselt

Die eigentliche Datenverschlüsselung erfolgt mit symmetrischen Verfahren wie AES.
Der Schlüsselaustausch läuft asymmetrisch (z. B. RSA oder ECC).

Das ist das gleiche Prinzip wie HTTPS.

Zusammenfassung

SMTP transportiert E-Mails zwischen Servern.
POP3 lädt Mails herunter und speichert sie lokal.
IMAP synchronisiert Mails serverbasiert zwischen mehreren Geräten.

POP3 ist einfach, aber unflexibel.
IMAP ist moderner und für Mehrgerätebetrieb geeignet.

Alle Protokolle nutzen TCP.
Sicherheit erfolgt über TLS.

Mit hMailServer kann man das komplette System lokal nachbauen und die Protokolle per Telnet nachvollziehen. Und genau das macht das Verständnis plötzlich greifbar, statt nur theoretisch.
